# Domain docs

This repository uses a single-context layout:
root `CONTEXT.md` and `docs/adr/`.

Before exploring code, read `CONTEXT.md` and any ADRs relevant
to the area being changed. If these files are absent, proceed
silently; create domain documentation when terms or decisions
are resolved.

Use the glossary's vocabulary when naming domain concepts.
If a needed concept is missing, note the gap for domain modeling.
Surface conflicts with existing ADRs explicitly.
